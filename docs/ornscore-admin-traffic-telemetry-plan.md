## 1. 두 가지 데이터를 절대 섞지 말 것

관리자가 "우리 사이트 얼마나 들어와?"를 볼 때 실제로는 **성격이 완전히 다른 두 데이터**를 본다. 하나의 숫자처럼 합치면 안 된다.

| 구분 | (A) 로그인 활동 | (B) 익명 접속(페이지뷰·유입) |
|---|---|---|
| 정체 | 신원 있는 계정 이벤트 | 신원 없는 방문 집계 |
| 원본 | **Supabase Auth** (`auth.users`) | **Vercel Analytics** 대시보드(외부) |
| 조회 위치 | `/admin/users` (service role, 서버 전용) | vercel.com/analytics (오너 계정) |
| 대표 지표 | 가입 수·오늘/7일/30일 로그인·미로그인·제공자 | 페이지뷰·방문자·유입 경로(referrer)·경로별 트래픽 |
| 개인 식별 | 이메일 등 **직접 식별자 포함** | 개별 신원 없음(집계·근사) |
| 앱 안에 이미 있나 | 예 (`/admin/users`가 정본) | 아니오 (외부 대시보드가 정본) |

핵심: **로그인 수 ≠ 방문자 수.** 로그인은 (A)의 부분집합이고, 실제 트래픽 대부분은 (B)의 비로그인 방문이다. `/admin/users`의 "오늘 로그인 N명"을 "오늘 방문 N명"으로 읽으면 안 된다.

### 지금 코드가 이 둘을 어떻게 다루나 (현행 인벤토리)

- **(A) 로그인 활동** — `src/app/admin/users/page.tsx`가 `supabase.auth.admin.listUsers()`로 최대 500명 스캔 후 파생 지표 계산(`recentSignups`·`todayLogins`·`recentLogins`·`monthlyLogins`·`neverSignedIn`). service role 키는 서버에서만 쓰이고 클라이언트 번들·공개 화면에 노출되지 않음(`createAdminClient` + `/admin` 미들웨어 + `ADMIN_EMAILS` 허용목록).
- **(B) 익명 접속** — `src/app/layout.tsx`에 `<Analytics />`(`@vercel/analytics/next`)가 마운트돼 페이지뷰·유입이 **Vercel 대시보드로만** 흘러간다. 커스텀 이벤트는 `src/lib/clientAnalytics.ts`(`trackEvent`)와 `AnalyticsEventTracker.tsx`(`data-analytics-event` 클릭)로 보강(이벤트 목록은 event-map 문서). **관리자 화면에는 (B)를 읽어오는 코드 경로가 없음** — 의도적 경계.
- **현행 안내 카피** — `/admin/users`의 "전체 접속·페이지뷰" InfoBlock이 이미 이 경계를 문장으로 안내하고 Vercel Analytics로 링크한다. 이 노트는 그 카피의 **배경 근거와 다음 단계**를 문서로 고정하는 것이며, 카피를 대체하지 않는다.

## 2. 프라이버시 · 데이터 보존 주의 (익명 트래픽을 관리자로 가져올 때)

익명 페이지뷰·유입을 "익명이니까 안전"으로 넘기면 안 된다. 관리자 안으로 끌어오는 순간 아래가 리스크가 된다.

1. **유입 경로(referrer)는 준-식별정보가 될 수 있다.** referrer URL에 검색어·내부 캠페인 토큰·외부 서비스의 유저 파라미터가 붙어 오는 경우가 있다. 원본 referrer를 그대로 저장·표시하면 "익명"이 깨질 수 있음 → 도메인/호스트 단위로 축약해서만 보관.
2. **IP·User-Agent는 개인정보에 준한다.** 원시 IP를 로그로 남기면 보존·파기 정책 대상이 된다. 집계(국가/디바이스 클래스)로만 다루고 원시값은 저장하지 않는 것을 기본값으로.
3. **원시 검색어·신고 본문·이메일·자유입력은 이벤트로 보내지 않는다** (event-map §Privacy Rules와 동일 원칙). 새 트래픽 수집을 붙일 때도 이 금지선을 그대로 상속.
4. **보존 기간을 먼저 정하고 수집한다.** 자체 이벤트 테이블을 만들면 "언제 파기하나"가 즉시 정책 문제가 된다. 권장: 원시 이벤트는 짧은 롤링 윈도우(예: 30–90일) 후 집계본만 남기고 원시 삭제. 정본 정책은 [`/privacy`](../src/app/privacy/page.tsx)·데이터 삭제 흐름과 **한 문장도 어긋나지 않게** 맞춰야 함.
5. **공개 문서와의 일관성.** `/privacy`가 "Vercel Analytics로 익명 집계를 본다" 수준으로 고지돼 있다면, 관리자 내 자체 수집을 추가하는 순간 공개 고지도 함께 갱신해야 한다(오너 게이트). 코드보다 고지가 뒤처지면 안 됨.
6. **동의·법적 근거.** 자체 식별 가능 트래픽 로그를 신설하면 쿠키/동의 배너·개인정보처리방침 항목이 새로 필요할 수 있음 → 순수 기술 작업이 아니라 **법무 판단이 선행**하는 오너 게이트.

> 요약: 지금처럼 (B)를 **Vercel Analytics에 위임**하면 위 대부분을 벤더가 흡수한다. 자체 수집으로 옮기는 순간 보존·파기·동의·고지 책임이 우리에게 넘어온다 — 이게 아래 선택지의 핵심 트레이드오프.

## 3. 관리자 내 트래픽 대시보드 선택지 (전부 오너 게이트 · 이번 배치 미구현)

익명 트래픽을 관리자 화면 안에서 보고 싶어질 때의 후보. 비용·리스크 오름차순. **어느 것도 이 배치에서 구현하지 않음.**

### 옵션 A — 현행 유지: 외부 위임 + 링크 (구현 0, 권장 기본)
- 지금처럼 (B)는 Vercel Analytics 대시보드가 정본, `/admin/users` InfoBlock이 그리로 링크.
- 장점: 보존·파기·동의를 벤더가 부담. 코드·정책 변경 0. 이미 동작.
- 한계: 관리자 화면 한 곳에서 (A)+(B)를 나란히 못 봄. 트래픽 보려면 창을 바꿔야 함.
- **오너 판단 필요**: 없음(현상 유지). 다음 옵션으로 갈 이유가 생길 때만 재검토.

### 옵션 B — 읽기 전용 임베드/딥링크 강화 (경량, 정책 변화 최소)
- 자체 수집 없이, `/admin`에 Vercel Analytics 대시보드로 가는 **맥락형 딥링크/카드**만 보강(예: 경로별·기간별 링크 프리셋). 데이터는 여전히 벤더에 있음.
- 장점: 새 테이블·수집 0 → 프라이버시 표면 불변. UI 편의만 향상.
- 한계: 여전히 화면 이탈. Vercel 임베드 위젯은 인증/iframe 제약이 있어 대개 링크가 현실적.
- **오너 게이트**: Vercel 대시보드 접근은 오너 계정. 링크 URL 구조만 코드에 둠(계정 작업 아님).

### 옵션 C — 벤더 API 서버측 풀 (중간 비용, 자체 저장 없음)
- Vercel Analytics/로그 API(또는 유사 벤더 API)를 **서버에서 읽어** `/admin`에 요약 카드로 표시. 원시 데이터는 우리 DB에 저장하지 않고 조회 시점에만 표시.
- 장점: (A)+(B)를 한 화면에. 자체 보존 부담 없음(캐시만).
- 필요 조건(전부 오너 게이트): 벤더 API 토큰(새 env·계정 권한), 새 서버 라우트, 레이트리밋·에러 폴백 설계, 캐시 TTL. → **새 API 라우트·외부 계정 작업이라 이 배치 범위 밖.**
- 리스크: 벤더 API 스키마 의존·비용·요율 한도. 토큰 유출 시 트래픽 데이터 노출.

### 옵션 D — 자체 이벤트 테이블 (최대 비용·최대 책임)
- Supabase에 익명 페이지뷰/유입 이벤트 테이블을 신설하고 우리가 직접 적재·집계.
- 장점: 완전한 소유·커스텀 지표·무제한 질의.
- 비용·리스크(전부 선결 오너 게이트):
  - 새 테이블 + RLS + 인덱스 + 적재 API 라우트(서버) + 집계 쿼리.
  - **§2의 보존·파기·동의·고지 책임 전부 우리 것**이 됨. `/privacy`·데이터 삭제 흐름 동시 갱신 필수.
  - 봇/중복/스팸 필터, 카디널리티 폭증(경로·referrer) 관리, 테이블 성장·비용.
- 결론: 트래픽 규모가 벤더로 부족할 만큼 커지고 커스텀 지표가 사업상 필요해질 때만. **현시점 과잉.**

### 권장 경로
현행 = **옵션 A**. 관리자 한 화면에 (A)+(B)를 붙이고 싶어지면 먼저 **옵션 B**(정책 변화 0). 벤더 링크로 부족할 때만 **옵션 C**를 오너 승인 하에 검토. **옵션 D는 명확한 사업 근거가 생기기 전엔 보류.**

## 4. 이번 배치가 한 것 / 안 한 것 (경계 고정)

- **한 것**: 이 설계 노트 1건(docs-only). (A)/(B) 개념 분리, 현행 코드 인벤토리, 프라이버시·보존 주의, 미래 대시보드 4선택지 정리.
