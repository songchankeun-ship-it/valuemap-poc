## 1. 데이터 상태 이력 공개 (브리프 고도화 #6)

### 현황
- `/status`(`src/app/status/page.tsx`)와 `src/lib/dataStatus.ts`는 **현재 스냅샷 1개**만 표시한다:
  가격 기준일(`asOfBusinessDate`), 점수 생성 시각(`generatedAt`, KST/UTC), 산식 버전, 종목별 지연 요약, 자동 점검 요약.
- 빌드에 포함된 `public/data/stocks.json` 메타데이터는 **단일 시점 값**이다
  (`generatedAt`, `asOfBusinessDate`, `pricesSyncedAt`, `metricsVersion`, `count`, `source`).
- 산식 **버전** 이력은 이미 `/guide/metrics/changelog`에 존재하나, 이는 "지표 산식 변경 이력"이지
  "일자별 데이터 파이프라인 상태 이력"이 아니다.

### 결론: 이번 슬라이스에서 라이브 이력 표면 추가 안 함 (정직성)
- 진짜 "데이터 상태 이력"은 **과거 스냅샷의 시계열**을 요구한다. 현재 빌드에는 과거 상태가 보존되지 않는다.
  (과거 값은 git 히스토리의 `stocks.json`에만 존재 → 런타임에서 조회 불가.)
- 단일 스냅샷을 "이력"으로 렌더하면 1행짜리 가짜 이력이 되어 사용자를 오해시킨다 → **하지 않음**.
- 따라서 정직한 선택은 **다음 작업으로 정밀 문서화**(아래).

### 다음 작업 정밀 스펙 (append-only 스냅샷 로그)
1. **수집/생성 단계(cron)에 append 훅 추가**: 매 생성마다
   `public/data/status-history.json`(append-only, 최근 N=30~60개만 유지)에 아래 레코드 1개를 추가.
   ```json
   {
     "generatedAt": "2026-07-10T09:41:59Z",
     "asOfBusinessDate": "20260709",
     "pricesSyncedAt": "…",
     "metricsVersion": "2.4",
     "universeCount": 138,
     "suspectCount": 3,
     "missingFinancialsCount": 0,
     "priceLagCount": 1
   }
   ```
   - 이는 **수집 코드 변경**이므로 표시 전용 슬라이스 밖 — 별도 배치에서 데이터셋 정책과 함께 처리.
   - 값은 이미 `dataStatus.selfCheck` / `getPriceLagSummary()`가 계산하는 것과 동일 → 지어내지 않음.
2. **표시부**: `/status`에 "데이터 상태 이력" 섹션 추가 — `status-history.json`을 읽어 일자·기준일·산식버전·지연종목수·검증보류수를 표로.
   파일이 없으면 섹션 자체를 렌더하지 않음(graceful, 기존 `insider-signals.json` 폴백 패턴과 동일).
3. **검증**: 로그가 append-only·상한 유지되는지 스크립트 점검, `/status` SSR에 이력 표 렌더 확인.

> 요약: 표시부는 작지만 **선행 조건이 수집 단계의 스냅샷 로그 영속화**라, 표시 전용 슬라이스로는 완결 불가.
> 로그가 쌓이기 시작한 시점부터 이력이 의미를 갖는다.

## 2. 종목 상세 차트 마커 (브리프 P2 #5 후단 / 고도화 #2)

브리프 제안 5종 레이어의 **현재 데이터로의 파생 가능성**:

| 마커 | 필요 데이터 | 현재 빌드에 있나 | 이번 슬라이스 |
|---|---|---|---|
| 최대낙폭 구간 | 종가 시계열 `c` | ✅ `prices/{ticker}.json` | ✅ 파생(고점/저점 거래일) |
| 3개월 급등 경고 구간 | 종가 시계열 `c` | ✅ | ✅ 파생(≥ +40% 시) |
| 거래량(거래활성도) 급증일 | 거래량 시계열 `v` | ✅ | ✅ 파생(직전 20일 중앙값 3배) |
| 점수 급등·급락 마커 | **일별 점수 시계열** | ❌ (Supabase `daily_scores`, 빌드 밖) | ⛔ 다음 작업 |
| 공시 마커 | **공시일↔가격일 정합** | ⚠️ DART/insider API는 있으나 정적 정합 파일 없음 | ⛔ 다음 작업 |

### 이번 슬라이스에서 구현한 최소분 (진짜 데이터만)
- `src/lib/priceSummary.ts` — 순수 `computeChartEvents(points)` 추가.
  이미 받은 `d/c/v`만으로 마커 **후보 이벤트** 파생: 최대낙폭 고점/저점 거래일, 3개월 급등 구간(임계 이상),
  거래량 급증일 수·최근 급증일. 임계 미달·이력 부족은 null/0(graceful). 점수·공시 마커는 만들지 않음.
- `src/components/StockPriceSummary.tsx` — 기존 텍스트 fallback 블록(Task 138)에 "관측된 이벤트 (참고)"
  소섹션을 추가해 위 이벤트를 **텍스트로** 노출(서버 렌더 → 검색엔진·스크린리더도 읽음).
  이는 곧 차트 마커의 SEO/접근성 표현이자, 미래 오버레이가 소비할 단일 소스의 첫 소비처.
- `scripts/test_priceSummary.ts` — `computeChartEvents` 회귀 가드(낙폭 날짜·급등 임계 경계·거래량 급증) 추가.

임계값(문서화): 3개월 급등 = 63거래일 등락률 ≥ +40%(`SURGE_3M_THRESHOLD_PCT`);
거래량 급증 = 직전 20거래일(`VOLUME_SPIKE_BASELINE`) 거래량 중앙값의 3배(`VOLUME_SPIKE_MULTIPLE`) 이상,
최근 약 3개월(`VOLUME_SPIKE_WINDOW`=63거래일) 구간에서 집계.

### 차트 오버레이 본구현 — Task 152에서 완료(진짜 데이터 파생분)
`StockPriceChart`(클라이언트 SVG)의 `computeMarkers(filtered)`가 표시 범위 종가·거래량에서만
아래 오버레이를 그린다. 새 데이터/API 없음, 임계 상수는 `priceSummary`(= `computeChartEvents`)와 공유:
- **거래량 급증 점 마커** — 직전 `VOLUME_SPIKE_BASELINE`(20)거래일 중앙값의 `VOLUME_SPIKE_MULTIPLE`(3)배 이상,
  강도 상위 3개만(모바일 혼잡 방지). (기존 2.5배·평균 → 3배·중앙값으로 텍스트 요약과 일치화.)
- **고점→저점 낙폭 구간 음영** — 표시 구간 −10% 이상 낙폭일 때 고점~저점 밴드 + 저점 점 마커.
  (기존 저점 점 1개만 → 하락 "구간"을 음영으로 표시해 인사이트 강화.)
- **최근 약 3개월(63거래일) 급등 밴드** — 표시 범위에 3개월 이상 이력이 있고(6개월·1년 토글) 등락률 ≥
  `SURGE_3M_THRESHOLD_PCT`(+40%)일 때 우측(최근) 구간 밴드. 3개월 이하 토글에서는 baseline 부족으로 자동 미표시.
- 톤은 호재/악재 아님을 명시(중립 색 + 하단 캡션 "호재·악재 판단 아님" + 호버 툴팁 "확인 유도").
  범례에 지점·구간 종류 표시, **지점 보기/숨기기 토글**로 접근성 유지. 밴드는 기존 280px SVG 내부에만 그려
  차트 높이·가로 오버플로 변화 없음.

### 남은 마커(아직 진짜 데이터가 차트에 연결돼 있지 않음 — 지어내지 않음)
1. **점수 급등·급락 마커** — *필요 데이터 훅*: 빌드 타임에 Supabase `daily_scores`에서 종목별 일별 종합점수
   시계열을 정적 파일(`public/data/score-history/{ticker}.json`)로 내려 페이지가 차트에 `scorePoints`로 주입.
   그 뒤 급변(임계 Δ) 거래일을 가격일에 스냅해 마커화. **새 생성 데이터셋** → 데이터 정책 배치에서.
   현재 차트에는 점수 시계열이 전혀 스레드돼 있지 않아 이번 슬라이스에서 만들지 않음.
2. **공시 마커** — *필요 데이터 훅*: DART 공시일 ↔ 가격 거래일 정합 정적 파일
   (`public/data/disclosure-markers/{ticker}.json`, 공시일을 가장 가까운 거래일에 스냅 + 가격 캘린더와 검증)
   생성이 선행. `insider-signals.json`/공시 API는 있으나 날짜 정합 파일이 없어 차트에 안전히 연결 불가 → 다음 배치.
