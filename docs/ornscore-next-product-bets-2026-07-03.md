# 오른스코어(OrnScore) 다음 제품 베팅 숏리스트 — 폴리시 웨이브 이후 (2026-07-03)

> **목적**: 폴리시 웨이브(Task 167~177)로 외부 피드백 노출 준비가 로컬 기준 GO에 도달한 지금, **다음에 실제로 손댈 의미 있는 방향 하나를 고르기 쉽게** 후보를 랭크로 정리한다.
> **성격**: 이 문서는 **문서 전용 · 소스 무변경**. 새 기능·리팩터링·데이터/산식 변경 0. 각 베팅은 이미 추적 중인 설계서 항목으로 **링크만** 걸고 재서술하지 않는다. 신규 코드 스캐폴드 0.
> **불변식 재확인**: 무료·한국어 전용 베타·138종목·비자문·확정가/Pro 비홍보 — 전부 유지. 금칙어(매수·매도·추천·수익 보장·목표가) 신규 도입 0.
> **위치**: 이 숏리스트는 무엇도 대체하지 않는다. **근시일 자동화 큐는 여전히 [`ornscore-owner-review-2026-07-03.md`](./ornscore-owner-review-2026-07-03.md) §3 / [`ornscore-spec-coverage.md`](./ornscore-spec-coverage.md) §A의 ③ 소작업 백로그**이고, 이 문서는 그 이후 "한 단계 큰 방향"을 오너가 고르기 위한 참고다.

## 읽는 법

- **랭크 기준**: (사용자 가치 × 차별성) ÷ 오너 게이트 의존도. 즉, 체감이 크고 오른스코어를 남과 다르게 만들면서, 개발이 단독으로 더 멀리 밀 수 있는(사람/법무/유료계정 의존이 낮은) 순으로 위에 둔다.
- **필드**: **Effort**(S/M/L) · **Risk** · **오너 전용 의존**(④ 큰 데이터/제품 결정 · ⑤ 사람/법무/사업 — 어떤 게이트인지 명시) · **다음 로컬 첫 작업**(오너 게이트 없이 **지금** 가능한 ③ 문서/표시 수준 작업 — 스캐폴드 아님).
- **첫 작업 규칙**: 전부 `stocks.json`·점수식·`direction`·인증·알림 배선 무변경으로 가능한 표시/문서 작업. 파이프라인·결제·발송 배선은 첫 작업에 포함하지 않는다(그건 각 베팅의 오너 게이트).

## 1. 관심 종목 고도화 — 그룹·메모·CSV (리텐션 코어)

리텐션 루프의 다음 단계. 담기/제거·실행취소·정직 프레이밍은 이미 완료(Task 148·156·160)라, 다음은 "담은 것을 조직화·반출"이다. 알림 라이브 없이도 재방문 가치를 키우는, **오너 게이트가 가장 얕은** 베팅.

| 필드 | 값 |
|---|---|
| Effort | **M** |
| Risk | 낮음 — 로컬 저장(localStorage/Supabase) 확장, 점수식·데이터 무관 |
| 오너 전용 의존 | **④ [제품/개발]** — 그룹·메모·CSV는 신규 기능 설계(데이터 모델·동기화 정책). 결제/법무/스토어 게이트 **없음** |
| 다음 로컬 첫 작업 | 그룹/메모 저장 스키마 + CSV 반출 컬럼 정의 + "로컬 기록" 정직 프레이밍을 **설계 노트로** 정리(스캐폴드 아님). 기존 `watchlist.ts` 패턴·Task 160 프레이밍 재사용 |
| 근거(링크) | spec §2 **8.2** ([`ornscore-spec-coverage.md`](./ornscore-spec-coverage.md)) · owner-review §2 관심 |

## 2. 데이터 설명가능성 — 점수 근거 심화 · 공시 중요도 · 공시 후 반응

오른스코어의 신뢰 차별점("왜 이 점수인가")을 한 단계 더. 점수 근거 보기(`scoreBasis.ts`/`ScoreBasisBreakdown`)는 이미 ①이라 **표시 심화는 거의 ③**, 공시 중요도(시총 대비 규모)·공시 후 반응 통계(이벤트 스터디)는 데이터가 필요한 ④. 신뢰가 곧 상용화 준비도라 ROI 높음.

| 필드 | 값 |
|---|---|
| Effort | 근거 심화 **S** / 중요도·이벤트 스터디 **L** |
| Risk | 근거 심화 낮음(표시) · 이벤트 스터디는 데이터 품질·과최적화 해석 리스크 |
| 오너 전용 의존 | **④ [개발]** — 공시 중요도 산출 모델·"최근 3년 유사 공시 N건 평균 수익률" 파이프라인. 법무/결제 게이트 **없음** |
| 다음 로컬 첫 작업 | `ScoreBasisBreakdown` 지표별 기여 설명 카피를 한 단계 더 명료화(③ 표시) **또는** 공시 중요도 휴리스틱 입력값(시총 대비 규모·과거 반응)·이벤트 스터디 데이터 요건을 **설계 노트로** 사전 스코핑 |
| 근거(링크) | spec §2 **5.1·6.2·6.4** ([`ornscore-spec-coverage.md`](./ornscore-spec-coverage.md)) |

## 3. 공시 전체 기간 수집 파이프라인

공시가 핵심 차별점인데 현재는 "최신 200건 내" 임시안. 종목 단위 DART 조회 + 영속 커서로 바꾸면 관심 종목 공시 알림·종목 상세 공시가 전 기간을 커버. 법무/결제 없는 **순수 데이터 파이프라인 ④**라 방향이 명확.

| 필드 | 값 |
|---|---|
| Effort | **L** |
| Risk | 중간 — DART 페이지네이션·레이트리밋·영속 저장 신규. 표시 배선은 이미 존재 |
| 오너 전용 의존 | **④ [개발]** — 전 기간 수집·저장 파이프라인. 결제/법무 게이트 **없음** |
| 다음 로컬 첫 작업 | 종목 단위 DART 조회 + 영속 커서 설계 노트를 확장(스캐폴드 아님). Task 93이 이미 [`ornscore-beta-launch-checklist.md`](./ornscore-beta-launch-checklist.md) (g)에 준비 노트를 둠 → 그 위에 스키마/커서/백필 순서만 상세화 |
| 근거(링크) | spec §1 **D 19.2** · §2 6 ([`ornscore-spec-coverage.md`](./ornscore-spec-coverage.md)) · local-release-evidence (d)-5 |

## 4. 종목 커버리지 확대 138 → 500

가장 직접적인 사용자 가치("내 종목이 없다" 해소). 단계적(KOSPI200·KOSDAQ150·ETF → 상위 500 → 전체)이며 데이터 품질 관리가 동반되는 ④. 결제/법무 없음.

| 필드 | 값 |
|---|---|
| Effort | **L** |
| Risk | 중간 — 종목 증가 시 결측/이상데이터 검증 부담·"검증 보류" 종목 관리 |
| 오너 전용 의존 | **④ [개발]** — 데이터 품질 파이프라인·단계 확장 결정. 결제/법무 게이트 **없음** |
| 다음 로컬 첫 작업 | 1단계 유니버스(KOSPI200·KOSDAQ150·ETF) 선정 기준 + 단계별 데이터 품질 게이트 체크리스트를 **설계 노트로** 상세화. Task 47이 이미 [`ornscore-beta-launch-checklist.md`](./ornscore-beta-launch-checklist.md) (c)에 단계·주의·`dataStatus.knownLimits` 노출을 둠 → 그 위에 게이트만 구체화(데이터 무변경) |
| 근거(링크) | spec §2 **10** ([`ornscore-spec-coverage.md`](./ornscore-spec-coverage.md)) · local-release-evidence (d)-6 |

## 5. 알림 선호 → 라이브 발송

사용자 가치는 크지만 **오너 게이트가 가장 무겁다**. UX(9종 카탈로그·채널 현황·미리보기·정직성)와 무발송 백로그(Stage 1~4)는 이미 완료(Task 45·144·148·171). 남은 라이브화는 채널 계정·발신프로필·템플릿 심사·건당 과금(④/⑤). 게이트 의존도가 높아 랭크는 아래.

| 필드 | 값 |
|---|---|
| Effort | 이메일 임계 튜닝 **M** / 카카오·웹·푸시 채널 **L** |
| Risk | 높음 — 실발송은 스팸/오탐·비용·심사 리스크. 무발송 불변식이 깨지는 지점 |
| 오너 전용 의존 | **④/⑤ [제품·사업·법무]** — 채널 계정·발신프로필·**템플릿 심사·대행사·건당 과금**·종류별 Supabase 스키마. 오너 입력값 없이는 라이브 불가 |
| 다음 로컬 첫 작업 | 어떤 알림 종류를 먼저 라이브로 올릴지(이메일 우선) vs 채널 계정이 선결인지 **우선순위 노트로** 정리 — 기존 [`ornscore-kakaotalk-alert-backlog.md`](./ornscore-kakaotalk-alert-backlog.md) §3·§4 위에 순서만(무발송 유지) |
| 근거(링크) | spec §2 **5.4·7** ([`ornscore-spec-coverage.md`](./ornscore-spec-coverage.md)) · [`ornscore-kakaotalk-alert-backlog.md`](./ornscore-kakaotalk-alert-backlog.md) · local-release-evidence (d)-4 |

제품 결정은 이미 "Android TWA 우선"(2026-07-01)이고 준비 문서(결정 트리·에셋·게이트·오너 인테이크)도 있다. 다만 남은 건 전부 **사람만 할 수 있는 것**(서명 SHA-256 지문·Play $25 계정·실기기 QA)이라, 개발이 지금 더 밀 여지가 가장 좁아 랭크 최하위.

## 추천 — 먼저 고를 1~2개

**#1 관심 종목 고도화(그룹·메모·CSV)** 를 첫 베팅으로 권한다: 오너 게이트가 가장 얕아(결제·법무·스토어 무관) 개발이 단독으로 끝까지 밀 수 있고, 리텐션 루프의 자연스러운 다음 칸이라 폴리시 웨이브와 결이 이어진다. 병행/차선으로 **#2 데이터 설명가능성의 점수 근거 심화**(거의 ③ 표시 작업)를 얹으면 신뢰 차별점을 낮은 리스크로 키운다. 반대로 **#5 알림 라이브·#6 TWA 래퍼**는 가치가 크더라도 오너 입력값(채널 계정·서명 지문·실기기)이 선결이라, 그 게이트가 열리기 전까지는 각 베팅의 "다음 로컬 첫 작업"(설계·우선순위 노트)까지만 로컬에서 준비하는 것이 안전하다.

> 이 숏리스트는 무엇도 대체하지 않는다. 근시일 자동화 큐는 여전히 `owner-review §3` / `spec-coverage §A`의 ③ 소작업 백로그이며, 이 문서는 그 이후의 "한 단계 큰 방향" 선택을 돕는 참고 레이어다.
