# 오른스코어 첫 방문 UX 대정리 설계서

- 작성일: 2026-07-14
- 상태: 구현 기준선 확정안
- 범위: 공개 웹/PWA의 첫 방문, 반복 방문, 종목 탐색, 종목 상세, 관심/비교, 로그인 경계
- 제외: 점수 산식, 데이터 생성, Supabase 스키마/RLS, OAuth 제공자 설정, 결제, 앱스토어 콘솔, 배포

## 0. 결정 요약

오른스코어는 기능이 부족한 상태가 아니다. 현재 문제는 기능과 설명이 한 화면에 너무 많이 겹쳐 사용자가 서비스의 핵심 행동을 빠르게 고르기 어렵다는 것이다.

이번 작업의 목표는 기능 추가가 아니라 아래 한 문장을 실제 화면 구조로 만드는 것이다.

> 오른스코어는 오늘 확인할 한국 주식 후보를 줄이고, 그 이유와 원문 확인 순서를 보여주는 탐색 도구다.

완료된 화면은 처음 방문한 사용자가 10초 안에 다음 세 가지를 이해해야 한다.

1. 이 서비스가 무엇을 해주는지
2. 지금 누를 한 가지 행동이 무엇인지
3. 점수만 믿지 않고 무엇을 확인해야 하는지

이번 패스에서는 새 대시보드, 새 데이터, 새 점수, 새 알림 기능을 만들지 않는다. 기존 기능을 역할별로 분리하고 중복을 제거하며, 로그인과 관리자 기능을 공개 탐색 흐름에서 분리한다.

## 1. 현재 문제와 근거

### 1.1 공개 홈의 정보 과밀

2026-07-14 공개 홈 점검 기준으로 한 페이지에 다음 정보가 연속 노출된다.

- 히어로와 검색
- 시장 상태 숫자 카드
- 오늘 후보 3개
- 후보 사용 순서
- 공시 신호 3개
- 처음 사용 가이드
- 내 종목/최근 본 종목
- 핵심 기능 소개
- 사용 방법
- 투자 주의 고지
- 데이터 출처

SSR 기준 홈에는 링크 54개, 버튼 9개, 주요 제목 7개가 존재한다. 개별 요소는 유효하지만 전체로 보면 첫 행동보다 설명과 선택지가 많다.

### 1.2 같은 의미의 반복

- `오늘 먼저 볼 후보`가 히어로, 미리보기, 후보 섹션에서 반복된다.
- `어떻게 사용하나`가 후보 내부 순서, 처음 사용 가이드, 하단 사용법에서 반복된다.
- 비자문 고지가 사이드바, 홈 본문, 푸터에서 반복된다.
- 시장 상태가 상단 데이터 바, 히어로 배지, 시장 상태 카드, 하단 출처에서 반복된다.

반복은 신뢰를 높이기보다 중요한 정보의 우선순위를 약하게 만든다.

### 1.3 메뉴 명칭의 학습 비용

현재 `오늘`, `발견`, `관심`, `공시`는 짧지만 처음 온 사용자는 차이를 바로 알기 어렵다. 특히 `오늘`과 홈의 오늘 후보가 겹치고, `발견`은 종목 검색/필터 페이지라는 의미가 즉시 드러나지 않는다.

### 1.4 로그인 가치가 불명확

상단의 `로그인`, `시작하기`는 무엇이 달라지는지 설명하지 않는다. 비로그인 상태에서도 관심/비교가 로컬에서 작동하므로, 로그인은 기능 잠금 해제보다 여러 기기 동기화와 지속 기록의 가치로 설명해야 한다.

로컬 개발 환경에서 Supabase 자리표시자 때문에 관리자 로그인 흐름이 외부 실패 페이지로 나간 사건도 있었다. 공개 서비스 장애와 로컬 운영 설정 실패를 화면에서 명확히 분리해야 한다.

### 1.5 화면별 역할 경계가 약함

홈과 `/today`가 모두 오늘 후보와 시장 요약을 다루고, 홈과 `/stocks`가 모두 탐색 시작점 역할을 한다. 사용자는 어느 화면을 일상적으로 써야 하는지 학습하기 어렵다.

## 2. 제품 계약

### 2.1 핵심 사용자

#### A. 처음 온 개인 투자자

- 특정 종목을 검색하거나 오늘 볼 종목을 빠르게 좁히고 싶다.
- 점수 용어를 아직 모른다.
- 추천 서비스인지 분석 도구인지 확인하고 싶다.

#### B. 반복 방문 사용자

- 어제와 달라진 후보, 관심 종목, 공시를 확인하고 싶다.
- 매번 긴 서비스 설명을 다시 보고 싶지 않다.

#### C. 서비스 운영자

- 공개 사용자와 같은 동선을 방해하지 않고 운영 화면에 접근해야 한다.
- 관리자 화면 실패가 공개 서비스 실패처럼 보이면 안 된다.

### 2.2 핵심 사용자 작업

우선순위는 아래 순서로 고정한다.

1. 종목명/코드로 바로 찾기
2. 오늘 먼저 확인할 후보 보기
3. 후보가 된 이유 확인하기
4. 공시와 재무 원문 확인하기
5. 관심에 저장하거나 비교하기
6. 다음 방문에 변화 확인하기

### 2.3 하지 않는 것

- 매수/매도 추천
- 목표가 또는 수익 가능성 강조
- 점수를 하나의 투자 결론처럼 표현
- 로그인 강제
- 처음 방문자에게 관리자 기능 노출
- 기능을 설명하기 위한 마케팅 섹션 추가
- 데이터가 없는 기능의 가짜 미리보기

| `/today` | 오늘 무엇이 달라졌지? | 일일 브리핑 | 후보/공시/관심 변화 확인 |
| `/stocks` | 내 조건에 맞는 종목은? | 전체 종목 탐색과 필터 | 검색/프리셋/필터 |
| `/stock/[ticker]` | 왜 이 종목을 봐야 하지? | 근거와 확인 순서 | 요약 확인 후 원문/비교/관심 |

| `/login` | 로그인하면 무엇이 좋아지지? | 계정 가치 설명과 인증 | 제공자 선택 |
| `/admin/*` | 서비스 상태는? | 오너 전용 운영 | 운영 지표/사용자/신고 확인 |

## 4. 용어 기준

사용자에게 한 의미를 여러 이름으로 보여주지 않는다.

| 의미 | 화면 표기 | 사용 금지/축소 |
|---|---|---|
| 서비스 점수 | 탐색점수 | ORNScore, 우선도, 종합 80+ 혼용 |
| 오늘 목록 | 오늘 후보 | Top, 추천, 베스트 |
| 전체 목록 | 종목 찾기 | 발견만 단독 표기 |
| 저장 목록 | 관심종목 | 관심, 찜, 저장 혼용 |
| 공시 분류 | 공시 신호 | 호재/악재 점수 |
| 로그인 가치 | 여러 기기 동기화와 기록 유지 | 시작하기만 단독 표기 |
| 방법 설명 | 확인 순서 | 사용법, 가이드, 도움말 반복 |

점수 범위가 필요하면 `탐색점수 83/100`처럼 쓰고, `종합 80↑`는 필터나 상세 설명 안에서만 보조적으로 사용한다.

## 5. 공통 화면 원칙

### 5.1 한 화면, 한 주 행동

- 화면 상단에는 시각적으로 가장 강한 기본 행동을 하나만 둔다.
- 검색창은 입력 도구로 취급하며, 버튼 CTA와 경쟁시키지 않는다.
- 같은 목적지 링크를 한 섹션 안에서 두 번 반복하지 않는다.

### 5.2 설명보다 실제 데이터

- 기능 소개 카드 대신 실제 후보/공시/관심 변화 데이터를 보여준다.
- 실제 데이터가 없으면 기능을 꾸며 보여주지 않고, 짧은 빈 상태와 다음 행동을 제공한다.

### 5.3 점진적 공개

- 첫 화면: 결론과 첫 행동
- 두 번째 깊이: 근거
- 세 번째 깊이: 산식, 출처, 법적 고지

### 5.4 반복 방문 배려

- 첫 방문 설명은 닫거나 학습한 뒤 반복 노출하지 않는다.
- 최근 본 종목이나 관심종목이 있을 때만 개인 루틴을 홈에 노출한다.
- 개인 데이터가 없으면 빈 개인화 섹션을 홈에 추가하지 않는다.

### 5.5 신뢰 표현

- 데이터 기준일은 공통 데이터 바 한 곳을 주 표시로 사용한다.
- 페이지 본문에는 기준일이 판단에 필요한 위치에서만 보조 표기한다.
- 비자문 고지는 한 화면에 한 번만 본문에 두고, 푸터 고지는 유지한다.
- 데이터 지연/오류는 정상 상태와 색상, 문구, 아이콘이 분명히 달라야 한다.

## 6. 홈 개편 명세

### 6.1 홈의 역할

홈은 전체 기능을 소개하는 랜딩 페이지가 아니다. 실제 서비스를 바로 쓰는 시작 화면이다.

### 6.2 최종 섹션 순서

홈의 기본 렌더 순서를 아래 네 구간으로 제한한다.

1. 시작 영역: 서비스 정의, 검색, 오늘 후보 진입
2. 실제 후보 미리보기: 최대 3개
3. 확인 순서: 근거 → 비교 → 원문
4. 선택적 개인 루틴: 최근 본/관심 데이터가 있을 때만

하단에는 짧은 데이터 출처/비자문 문구와 관련 문서 링크만 둔다.

다음 기존 섹션은 홈에서 제거하거나 통합한다.

- `MarketSnapshotCards`: 후보 섹션의 보조 숫자로 통합
- `DisclosureSignalSection`: 홈에서는 최대 1개 티저 또는 `/today`로 이동
- `WelcomeOnboarding`: 상단 확인 순서 3단계로 통합
- `FeatureCards`: 제거
- `HowItWorksSection`: 상단 확인 순서로 통합
- `RiskNotice`: 푸터 전 짧은 1문장으로 축소
- `MyStocksSection`: 저장/최근 데이터가 있는 경우에만 렌더

### 6.3 첫 화면 카피

#### 제목

> 오른스코어로 오늘 확인할 한국 주식 후보를 줄여보세요.

#### 보조 설명

> 가격 흐름, 거래활성도, 밸류와 공시 신호를 함께 보고 왜 확인할 후보인지 정리합니다.

#### 기본 행동

- 검색 라벨: `종목명 또는 코드로 바로 찾기`
- 기본 버튼: `오늘 후보 3개 보기`
- 보조 텍스트 링크: `전체 종목에서 찾기`

#### 안전 문구

> 투자 추천이 아니라 확인 순서를 돕는 탐색 도구입니다.

안전 문구는 가치 설명과 실제 데이터 뒤에 위치시키며 배지, 카드, 푸터에서 같은 문장을 반복하지 않는다.

### 6.4 후보 카드 최소 정보

홈 카드에는 아래만 유지한다.

- 순번
- 종목명/코드/업종
- 현재가와 등락률
- 탐색점수
- 후보가 된 가장 강한 이유 한 줄
- 먼저 확인할 것 한 줄
- `상세 보기`
- `비교 담기`

4개 지표 전체, 긴 체크리스트, 중복 비교 CTA는 상세 또는 `/today`로 이동한다.

### 6.5 데스크톱 첫 화면

- 1280x720 기준 헤더/데이터 바 아래에 제목, 설명, 검색, 기본 CTA가 모두 보여야 한다.
- 첫 후보 카드의 상단이 같은 화면 아래쪽에 보여 다음 콘텐츠가 있음을 알려야 한다.
- 우측 별도 미리보기 패널은 후보 섹션과 정보가 겹치므로 제거한다.

### 6.6 모바일 첫 화면

- 390x844 기준 제목은 최대 3줄, 설명은 최대 3줄로 제한한다.
- 검색 입력과 기본 CTA가 첫 화면에 완전히 보여야 한다.
- 첫 후보 카드의 제목 또는 카드 상단이 첫 화면에 보여야 한다.
- 데이터 기준 배지는 한 줄을 넘지 않도록 짧은 날짜만 표시하고 상세는 공통 데이터 바에서 제공한다.
- 가로 스크롤, 겹침, 잘린 긴 종목명, 하단 내비게이션 가림이 없어야 한다.

## 7. `/today` 일일 브리핑 명세

홈과 역할이 겹치지 않도록 `/today`는 반복 방문자를 위한 변화 중심 화면으로 만든다.

최종 순서:

1. 오늘 한 줄 요약
2. 오늘 후보와 전일 대비 변화
3. 관심종목 변화(있을 때만)
4. 확인할 공시 신호
5. 데이터 기준/주의 사항

홈에 있는 서비스 설명, 기능 소개, 사용법 전체를 반복하지 않는다.

후보 카드에는 `왜 오늘인가`를 한 문장으로 표시한다. 단순히 현재 점수가 높다는 문장보다 점수/순위/거래활성도/공시 중 실제 변화가 있는 근거를 우선한다. 변화 데이터가 없으면 현재 강점임을 명확히 표시하고 변화처럼 표현하지 않는다.

## 8. 종목 찾기 명세

### 8.1 명칭

내비게이션의 `발견`은 `종목 찾기`로 바꾼다. 모바일 하단처럼 공간이 짧은 곳은 `찾기`를 허용한다.

### 8.2 첫 상태

- 검색 입력
- 결과 수
- 초보자용 질문형 프리셋 3~5개
- 활성 필터 요약
- 종목 카드/표

프리셋은 기능 설명 카드가 아니라 필터를 실제 적용하는 컨트롤이어야 한다.

### 8.3 필터 원칙

- 현재 적용된 조건을 칩으로 항상 확인할 수 있어야 한다.
- 초기화는 한 번에 가능해야 한다.
- 결과 0개일 때 조건 완화 방법과 초기화 버튼을 제공한다.
- 모바일에서는 필터가 결과 목록을 밀어내지 않도록 접힌 패널 또는 시트로 제공한다.

## 9. 종목 상세 명세

### 9.1 첫 화면 목표

사용자는 10초 안에 다음을 이해해야 한다.

- 어떤 종목인가
- 탐색점수가 얼마인가
- 왜 이 점수인가
- 가장 먼저 확인할 위험/원문은 무엇인가

### 9.2 상단 구조

1. 종목명, 코드, 업종, 기준일
2. 가격과 등락률
3. 탐색점수와 업종 내 위치
4. 한 줄 결론: `강점`과 `먼저 확인할 것`
5. 관심종목, 비교, 공유 행동

### 9.3 본문 구조

기본 탭은 요약으로 유지하되 아래 순서를 고정한다.

1. 점수 근거
2. 최근 변화
3. 최근 공시
4. 재무/밸류
5. 차트 또는 추가 분석

모든 상세 설명을 첫 화면에 펼치지 않는다. 사용자가 원할 때 탭 또는 `더 보기`로 깊이를 늘린다.

### 9.4 문장 규칙

- `좋다`, `나쁘다` 대신 관측된 데이터와 확인할 항목을 말한다.
- `상승 가능성`, `매수 기회` 같은 결론형 문장을 쓰지 않는다.
- 점수 근거와 원문 확인 CTA가 가까이 있어야 한다.

## 10. 관심종목과 비교 명세

### 10.1 관심종목

비로그인 사용자에게 로컬 저장이 작동함을 먼저 알려준다. 로그인은 다음 가치로만 설명한다.

- 여러 기기에서 이어보기
- 기록 유지
- 향후 변화 알림 준비

빈 상태에는 두 행동만 둔다.

- `오늘 후보에서 담기`
- `종목 찾아보기`

저장된 상태에서는 카드의 첫 줄에 최근 변화가 큰 항목을 우선 표시하고, 단순 저장 목록처럼 보이지 않게 한다.

### 10.2 비교

빈 상태에서 페이지 안에서 바로 종목을 추가할 수 있어야 한다.

- 검색으로 추가
- 오늘 후보에서 추가
- 관심종목에서 추가

최대 4개 제한을 선택 전에 표시한다. 모바일은 넓은 표만 제공하지 않고 기준 종목 대비 차이를 세로 카드로 읽을 수 있어야 한다.

## 11. 로그인과 관리자 경계

### 11.1 공개 로그인 CTA

`시작하기`처럼 의미가 없는 CTA를 단독 사용하지 않는다.

- 헤더: `로그인`
- 로그인 화면 제목: `관심종목과 기록을 여러 기기에서 이어보세요`
- 보조 설명: 비로그인에서도 탐색/로컬 저장이 가능함을 명시

### 11.2 설정 실패 처리

- Supabase URL/key가 없거나 자리표시자면 외부 인증 요청을 보내지 않는다.
- 비활성 상태에서 공개 홈과 종목 찾기로 돌아가는 링크를 제공한다.
- `사이트 오류`가 아니라 `이 환경에서는 로그인을 사용할 수 없음`으로 설명한다.
- 실제 비밀값을 화면, 로그, 문서에 출력하지 않는다.

### 11.3 관리자 화면

- `/admin/*`는 공개 내비게이션, 사이트맵, 검색 메타데이터에서 제외한다.
- 비로그인 사용자는 `/login?next=...`로 이동한다.
- 로그인했지만 관리자가 아니면 공개 홈 또는 명시적 권한 없음 화면으로 이동한다.
- 관리자 링크는 관리자 세션에서만 계정 메뉴에 표시한다.
- 관리자 설정 실패가 공개 페이지 렌더를 막지 않아야 한다.

## 12. 내비게이션 명세

### 12.1 데스크톱

주 메뉴:

- 오늘 브리핑
- 종목 찾기
- 관심종목
- 공시
- 비교

보조 메뉴:

- 실험실
- 지표 가이드
- 서비스 안내

`서비스 소개`는 푸터에 유지하고 주 내비게이션에서는 제외할 수 있다.

### 12.2 모바일 하단

- 오늘
- 찾기
- 관심
- 공시
- 더보기

`더보기`에는 비교, 실험실, 지표 가이드, 서비스 안내를 둔다. 홈은 상단 로고로 돌아간다.

### 12.3 메뉴 설명

처음 방문 시 한 번만 짧은 설명을 제공한다.

- 오늘: 오늘 달라진 후보와 공시
- 찾기: 전체 종목 검색과 필터
- 관심: 저장한 종목의 변화

항상 보이는 설명 문구나 별도 카드로 메뉴를 반복 설명하지 않는다.

## 13. 시각 및 상호작용 규칙

- 운영 도구가 아닌 공개 제품 화면의 카드 반경은 기존 캐논을 유지한다.
- 섹션 전체를 카드처럼 띄우지 않는다. 반복 항목이나 실제 도구만 카드로 표시한다.
- 파랑은 주 행동과 데이터 신뢰, 빨강/파랑은 국내 주가 등락, 주황은 지연/주의에 사용한다.
- 높은 점수를 강한 녹색이나 축하 표현으로 보여주지 않는다.
- 아이콘 버튼은 Lucide 아이콘과 접근 가능한 이름을 사용한다.
- 터치 대상은 44px 이상을 유지한다.
- 동적 숫자/배지/로딩 상태가 레이아웃 크기를 바꾸지 않도록 안정된 크기를 사용한다.
- 텍스트는 컨테이너를 넘지 않아야 하며 글자 크기를 뷰포트 너비로 비례 확대하지 않는다.

## 14. 상태 설계

각 핵심 화면은 아래 상태를 모두 가져야 한다.

| 상태 | 요구 사항 |
|---|---|
| 로딩 | 무엇을 불러오는지 짧게 표시, 무한 로딩 금지 |
| 빈 상태 | 실패처럼 보이지 않게 가치와 다음 행동 제공 |
| 부분 데이터 | 없는 필드만 숨기고 가능한 정보 유지 |
| 오래된 데이터 | 마지막 성공 기준일과 지연 상태 표시 |
| 오류 | 재시도와 공개 안전 경로 제공 |
| 인증 미설정 | 외부 요청 차단, 공개 홈/찾기 링크 제공 |
| 권한 없음 | 로그인 실패와 관리자 권한 부족을 구분 |

## 15. 분석 이벤트와 성공 지표

새 외부 분석 서비스를 추가하지 않는다. 기존 이벤트 계약을 사용하거나 로컬 검증 가능한 이벤트 이름만 추가한다.

### 15.1 필수 이벤트

- `home_primary_cta_click`
- `home_search_submit`
- `candidate_detail_click`
- `candidate_compare_add`
- `stock_watchlist_add`
- `stock_disclosure_open`
- `auth_cta_click`
- `login_provider_click`

이벤트에는 공개 경로, 공개 ticker/topic, UI source만 허용한다. 이메일, 검색 자유문, 신고 본문, 사용자 ID는 넣지 않는다.

### 15.2 출시 후 판단 지표

- 홈 방문 → 종목 상세 진입률
- 홈 방문 → 종목 검색 실행률
- 상세 방문 → 관심/비교 행동률
- 로그인 페이지 방문 → 제공자 선택률
- 홈 첫 화면 이탈률

숫자 대시보드가 아직 연결되지 않았으면 이벤트 계약과 검증기만 유지하고 가짜 수치를 표시하지 않는다.

## 18. 자동화 구현 슬라이스

작업은 아래 순서를 지킨다. 각 슬라이스는 하나의 로컬 커밋과 자체 검증 결과를 남긴다.

### Slice A. IA/용어와 회귀 기준 고정

- 공통 내비게이션 라벨을 역할 중심으로 정리
- 홈 중복 섹션 목록을 코드 기준으로 확정
- 첫 방문 UX 정적 검증기 초안 추가
- 데이터/점수/인증 변경 없음

완료 조건:

- 데스크톱/모바일 내비게이션 용어 일치
- `/`, `/today`, `/stocks` 역할이 카피에서 구분됨
- 정적 검증기가 중복 H1, 금지된 홈 섹션 재도입, 필수 CTA 누락을 실패 처리

### Slice B. 홈 시작 영역 단순화

- HomeHero를 단일 시작 영역으로 축소
- 우측 중복 미리보기 제거
- 제목/설명/검색/기본 CTA/짧은 안전 문구 정렬
- 390x844 첫 화면 위치 검증

완료 조건:

- 첫 화면에 서비스 정의, 검색, 기본 CTA가 보임
- 첫 후보 카드 시작점이 모바일 첫 화면에 보임
- CTA는 한 개가 시각적 주 행동

### Slice C. 홈 본문 중복 제거

- 시장 카드, 공시 목록, 온보딩, 기능 소개, 사용법, 위험 고지 중복 통합
- 후보 최대 3개와 확인 순서만 유지
- 개인 데이터가 있을 때만 최근/관심 섹션 표시

완료 조건:

- 홈 기본 섹션 수가 설계된 네 구간을 넘지 않음
- 같은 목적지 CTA 반복 없음
- 후보 카드에 이유/확인할 것/상세 행동이 존재

### Slice D. `/today` 변화 중심 재구성

- 홈과 중복되는 서비스 소개 제거
- 후보/공시/관심 변화 중심으로 순서 정리
- 변화 데이터가 없을 때 현재 강점과 구분

완료 조건:

- `/today`의 첫 문장이 오늘 달라진 내용을 설명
- 홈과 동일한 기능 소개 섹션 없음
- 관심 데이터가 없는 사용자에게 빈 카드 묶음을 보여주지 않음

### Slice E. 종목 찾기와 내비게이션 명료화

- `발견`을 `종목 찾기`/`찾기`로 정리
- 검색, 결과 수, 프리셋, 활성 필터의 시각 순서 정리
- 0건 결과 회복 동선 검증

완료 조건:

- 사용자가 메뉴명만으로 화면 역할을 이해할 수 있음
- 모바일 필터가 결과 첫 화면을 과도하게 밀어내지 않음
- 필터 초기화와 조건 완화 행동이 존재

### Slice F. 종목 상세 첫 행동 정리

- 상단 정보와 요약 탭의 중복 제거
- 결론 → 근거 → 최근 변화 → 공시 순서 고정
- 관심/비교/공유 행동의 우선순위와 모바일 위치 확인

완료 조건:

- 390x844에서 종목명, 가격, 탐색점수, 한 줄 근거, 기본 행동 확인 가능
- 점수 설명과 원문 확인 CTA가 논리적으로 가까움
- sticky 요소가 헤더와 겹치지 않음

### Slice G. 관심/비교/로그인 경계 정리

- 관심/비교 빈 상태의 행동 수와 문구 축소
- 비로그인 로컬 저장과 로그인 동기화 가치 구분
- 로그인 미설정/오류/권한 없음의 복구 경로 검증
- 관리자 링크 공개 노출 여부 검증

완료 조건:

- 비로그인 사용자가 기능 잠금으로 오해하지 않음
- 로그인 미설정 시 외부 자리표시자 URL 호출 0
- `/admin/*` 비로그인 보호와 공개 내비게이션 비노출 통과

## 20. 최종 출시 판정

아래가 모두 참일 때만 공개 반영 후보가 된다.

- 첫 방문 10초 질문 세 가지를 화면이 답한다.
- 홈의 반복 섹션과 경쟁 CTA가 제거됐다.
- 홈, 오늘, 찾기의 역할이 겹치지 않는다.
- 종목 상세 첫 화면에서 결론과 다음 행동을 찾을 수 있다.
- 비로그인 저장과 로그인 동기화 가치가 구분된다.
- 인증 미설정이 공개 서비스 장애처럼 보이지 않는다.
- 모바일/데스크톱 검증과 모든 로컬 게이트가 통과한다.
- 점수/데이터/Supabase/외부 설정에 비의도 변경이 없다.

푸시와 배포는 이 설계서의 자동화 범위가 아니다. 전체 슬라이스 완료 후 오너가 변경 요약과 화면 검증 결과를 확인하고 별도로 승인한다.
