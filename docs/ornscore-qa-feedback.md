## 4. P2 — 중요

### P2-1 · 공시 "수집 범위" 표기가 표면마다 달라 정밀 신뢰 메시지를 흐림
- **경로:** `/status`(데이터 종류별 상태) · `/disclosures` · `/stock/005380`(공시 탭)
- **재현 단계:**
  1. `/status` 또는 신뢰 모달에서 공시 항목을 본다 → **"DART · 최근 7일 · 최신 200건 분석"**.
  2. `/disclosures`로 이동 → 헤더 **"최근 7일 … 최신 200건 내"**, 단 사용자가 기간을 1~30일로 바꾸면 "최근 30일"로 바뀜.
  3. 임의 종목 상세(`/stock/005380`)의 공시 탭 → **"최근 90일 · 공시 N건 · 최대 20건 수집·10건 표시"**.
- **기대:** 데이터 신뢰 배지 제품답게, 공시 수집 범위가 표면 간 모순 없이 읽혀야 한다.
- **실제:** 셋은 **서로 다른 쿼리**(시장 전체 피드=7일 기본, 종목별=90일)라 사실 오류는 아니다. 그러나 `/status`의 글로벌 한 줄("공시는 최근 7일·최신 200건")만 본 사용자가 종목 페이지의 90일 공시를 보면 *왜 더 길지?* 혼동할 수 있다. 출처: `src/lib/dataStatus.ts:154`·`src/app/disclosures/page.tsx:35,43`·`src/components/StockDisclosures.tsx:145,150`.
- **제안:** `/status`·신뢰 모달의 공시 문구를 **범위가 표면별로 다르다는 점**을 한 줄로 흡수 — 예: "시장 전체 피드는 최근 7일(최신 200건), 종목별 상세는 최근 90일까지 조회". 코드 1~2줄 표시 수정(산식·데이터 무변경). *현재는 P2(혼동 가능)이며 데이터 정확성 문제는 아님.*

### P2-2 · `/today` 헤더의 "오늘 날짜" vs "데이터 기준일" 시각 위계 확인 필요
- **경로:** `/today`
- **재현 단계:** `/today` 접속 → 상단에 방문일 **"2026년 6월 26일 금요일"**(현재 날짜)과, 별도로 **"데이터 기준 … 장마감"**(2026.06.25)이 함께 노출.
- **기대:** 사용자가 "데이터가 오늘(6/26) 것"으로 오인하지 않아야 한다(데이터는 전 영업일 장마감 06.25).
- **실제:** 코드상 `/today`는 동적 렌더(ƒ)라 방문일은 항상 신선(=staleness 버그 없음). 두 날짜가 별도 라벨로 분리돼 있어 *논리적으로는* 정확. 다만 **방문일이 더 크게/먼저 보이면** 데이터 신선도를 오해할 여지 — 390px에서 두 줄이 붙으면 더 그럴 수 있다.
- **제안:** 운영자 육안에서 "데이터 기준 06.25 장마감"이 방문일과 명확히 구분되는지 확인. 필요 시 데이터 기준일에 약한 배경/배지를 줘 위계 분리(표시 수정). *기능 문제 아님 — 시각 위계 확인 항목.*

## 5. P3 — 개선 / 폴리시

### P3-1 · 핸드오프 문서(CLAUDE.md)에 구 브랜드 "밸류맵 스톡" 잔존 (문서 위생, 비-사용자노출)
- **경로:** `CLAUDE.md` (앱 아님)
- **실제:** 앱은 전 화면·메타데이터·도메인이 **"오른스코어 / ornscore.com"로 일관**(홈·요금제·about·status SSR에서 확인). 반면 `CLAUDE.md`는 여전히 "밸류맵 스톡"·`valuemap.kr`을 기준 브랜드로 서술 → 새 세션이 잘못된 브랜드로 작업할 위험.
- **제안:** `CLAUDE.md` 브랜드 절을 "오른스코어"로 정정(운영자/다음 세션). **사용자 노출 결함 아님** — 본 QA에서는 앱 일관성을 *확인 완료*로 본다.

### P3-2 · 설계서 ③(부분 구현) 항목 — 이미 백로그 추적됨, 신규 결함 아님
- 커버리지 문서(`ornscore-spec-coverage.md`) A절 ③로 추적 중: 현재 적용 조건 **자연어 한 줄** 요약 · 상세 필터 **예상 결과 수 실시간** · **압축형 보기** · **모바일 바텀시트 필터** · 5단계 신뢰 배지 풀세트 · 산식 불일치 **빌드 게이트**.
- **QA 메모:** 질문형 프리셋은 설계서 핵심 차별점인 **카드(설명+조건 배지+예상 결과 수+주의)까지 이미 구현**(`StocksExplorer.tsx:762~800`)으로, 커버리지 문서의 "부분" 평가보다 **완성도 높음**. 위 ③ 항목은 *없어서 깨진 것*이 아니라 *감각화 마감* 수준 → **사람 QA가 신규 버그로 재기재하지 말 것.**

### P3-3 · 공시 피드 종료일(라이브, 오늘) ≠ 가격 기준일(전 영업일) — 설계상 정상
- `/disclosures`는 라이브 DART 피드라 종료일이 당일(2026-06-26)까지, 가격·점수는 06.25 장마감. **서로 다른 신선도가 정상**이며 `domainStatuses`(가격/재무/공시/산식 분리)로 이미 고지됨. 혼동 방지 차원의 기록일 뿐 수정 불요.
